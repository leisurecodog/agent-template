# 程式規範（精簡版）

適用任何語言的通用結構／邊界／測試／Git 紀律。語言特定的規則見
`.claude/rules/*.md`（路徑限定，讀到對應檔案才載入）。

## 結構

- 不可變優先：回傳新物件，不就地修改傳入的參數。
- 檔案單一職責，一般 200–400 行，超過 800 行就該拆。
- 巢狀不超過 4 層；函式超過 50 行先想想能不能拆。

## 邊界防禦（不可省略）

- 系統邊界（使用者輸入、API 回應、檔案內容）必驗證，快速失敗、錯誤訊息講清楚。
- 錯誤不可靜默吞掉；對使用者的錯誤訊息友善，log 裡保留完整脈絡。
- 永不硬編碼 secrets；用環境變數，啟動時檢查必要變數存在。
- SQL 用參數化查詢；輸出到 HTML 先消毒。

## 測試（取代舊 testing.md 的 80% 強制規定）

- 非平凡邏輯（分支、迴圈、解析、金錢／安全路徑）至少留**一個可跑的檢查**：
  assert 式 `demo()`、`__main__` 自檢、或一個小 `test_*.py`。
- 一行工具函式不用測。使用者明確要求完整測試套件時才寫完整套件。
- 測試失敗時修實作不修測試，除非有證據證明測試本身錯。

## Git

- Commit 格式：`<type>: <description>`，type ∈ feat/fix/refactor/docs/test/chore/perf/ci。
- 使用者要求才 commit/push（push 與開 PR 屬 `judgment-rubrics.md` R3 必停）。在預設分支上先開新分支。
- 開 PR 前用 `git diff <base>...HEAD` 看全部改動，不只最後一個 commit。

## 動手前

- 先找既有實作：本 repo 的 helper → stdlib → 已裝依賴 → 才寫新的。
  新增依賴前先問自己能不能十行內解決。
- bash script 含中文輸出時，用 `printf '格式' "$var"` 分欄位組字串，勿把中文 literal 與
  `$變數` 放同一雙引號字串（macOS 系統 bash 3.2 的 UTF-8 bug 會把變數壞成 U+FFFD）。
- Commit 前檢查：無 secrets、邊界有驗證、錯誤有處理、非平凡邏輯有檢查可跑。
